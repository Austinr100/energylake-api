Why Neon and not the test cluster: the local cluster's timeseries_values holds 6 banked
rows, and on a 6-row table a Seq Scan is genuinely the cheapest plan whatever the indexes
exist — so a plan taken there would prove nothing about D-08-02-L. The suite's X1 cell
forces enable_seqscan = off and asserts the plan's SHAPE; THESE are the receipts.

Every read below names one (dataset, series) per LATERAL with the LIMIT pushed into it.
No read touches timeseries_values with a Seq Scan. Buffers are stated on every node.
